## Notes (minor, no change needed in P4)

- `test_eval_sh_refuses_fixture_rows_under_results` runs `eval.sh` against the real repo `results/`. If the T-8 guard ever regresses, the test writes fixture rows into the repo before it fails. My mutation run showed this: it left `results/fixture-*.jsonl`, `results/fixture-run/` and `results/summary.md` behind. The gate counts every `results/*.jsonl`, so a later phase could point the guard at a temporary copy of `RESULTS_DIR`. This only happens after a regression, so it is minor.
- For P5: `verify_model_dir` refuses any subfolder. A host download made with `huggingface_hub` into a `local_dir` usually leaves a `.cache/` folder there, so the host step should copy only the pinned files into the folder it gives the sandbox. The refusal is correct. This is a note for wiring P5, not a defect.
- `verify_model_dir` hashes the files, and the loader opens them later. That is the same check-then-use gap as T-10. The host hands the folder in read-only and the box has one user, so it stays low inside T-10.
