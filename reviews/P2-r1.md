## Findings

### TR-P2-r1-C1: stale duplicate fixture folder with a company name in its path

- Class: C (correctness of repo contents; standing constraint). Severity: medium.
- Evidence: `git ls-files fixtures/hm_like | wc -l` prints `44`. `diff -r fixtures/hm_like fixtures/shop_like` prints nothing (identical). `fixtures/hm_like/split.json` line 3 says `"dataset": "fixtures/shop_like (synthetic)"`. No code, test, contract or doc references `hm_like` (`grep -rn hm_like` outside the folder: no hits). `tests/contracts/test_contracts.py` line 32 checks only `shop_like` against the generator (`fixtures/make_fixtures.py` line 27, `OUT = ... / "shop_like"`), so the copy can drift unchecked. The PR body lists only `shop_like/`. The folder name abbreviates the retailer; the standing constraints keep company names to README prose and research notes.
- Fix: `git rm -r fixtures/hm_like`.

### TR-P2-r1-C2: per-category `pool_coverage` required by a red test but not defined

- Class: C. Severity: minor.
- Evidence: `tests/red/test_eval.py` `test_eval_sh_fixture_run`, last line, requires `{"ndcg@10", "recall@12", "recall@50", "pool_coverage"} <= set(r["metrics"])` for every row, and the test also requires rows with `table == "Tops"`. `contracts/eval.md` "Per-category tables" defines the filtered ranking and relevant set but not pool coverage for a category, and `contracts/seams.md` `category_metrics` returns no `pool_coverage`. P3c would have to guess the definition or write a Request for integration.
- Fix: one sentence in `contracts/eval.md` "Per-category tables": the category row's `pool_coverage` is `pool_coverage` over that table's customers with R filtered to g and the pool filtered to g; `eval.sh` computes it with `pool_coverage`, and `category_metrics` keeps its frozen return keys. `contracts/split.json` is untouched, so `split-sha256` is unchanged.
